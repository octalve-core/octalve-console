## Architecture and completion criterion
Console is the WHMCS-style commerce and lifecycle orchestrator **and** selected native customer hosting manager. DirectAdmin and cPanel/WHM are independent hosting systems; future OPanel is a separate adapter, not a prerequisite. One shared customer UI/API contract, provider-specific implementations, one Integration Store, one signed credential-bound authority, one billing ledger and one notification outbox. Do not fork the shared public/Console commerce design or duplicate existing components.

**Hosting mailbox** means an actual account such as info@example.com created on the customer's assigned hosting server, with its own password, quota and webmail/IMAP/SMTP. It is NOT Brevo/Resend transactional delivery. DNS means the correct authoritative zone, including separately verified external DNS authority (reuse existing Cloudflare integration). A hosting subdomain is an actual hosting resource, not merely a DNS record. Domain entry alone grants no DNS control. Native resources must not merely open the supplier panel or simulate success. Advanced file/database management can use secure supplier UI in addition to agreed basic native operations; no unrestricted proxy or replacement control panel.

After both batches, a supported supplier should require only administrative entry of server URL, public IP, restricted reseller credentials, password/authenticator confirmation, capability verification and package import, commercial pricing and policy configuration, controlled real-provider acceptance and explicit activation. No supplier-specific coding, secret duplication into Vercel or deployment per supported supplier. Unsupported versions or missing permissions remain disabled with truthful diagnostics. Platform-wide deployment, key custody and scheduler setup are distinct initial infrastructure prerequisites.
